# 蓝词同步与提醒规则

## 1. 文档说明

本文整理媒介同步蓝词数据时的字段范围、更新规则，以及工单发布前、视频发布后的提醒规则。

文中有两套「第一次 / 第二次」，含义不同：

| 说法 | 含义 |
| --- | --- |
| 同步第一次 / 第二次 | 媒介对同一条数据的同步次数 |
| 发布前第一次 / 第二次判断 | 工单发布前，随上述两次同步分别执行的提醒判断 |

## 2. 字段说明

| 中文名称 | 字段名 | 说明 |
| --- | --- | --- |
| 链接 | `url` | 视频或内容链接 |
| 蓝词 | `selected_blueword` | 选定蓝词 |
| 蓝词策略 | `blueword_execute_strategy_type` | 蓝词执行策略 |
| 内容形式 | `blueword_content_type` | 内容形式，提醒规则中涉及「合集视频」 |
| 是否抢蓝词 | `blueword_is_grab` | 是否需要抢蓝词 |
| 蓝词维护时长 | `blueword_maintain_duration` | 蓝词维护时长 |
| 供应商信息 | `blueword_suppliers` | 供应商数据。第二次同步时不按普通字段直接覆盖，见第 3 节 |
| KOC 预算 | `koc_budget` | 用于计算合作金额、执行费用比较 |
| 确认状态 | `is_need_confirm` | `3` 表示已确认 |

基础信息指除 `blueword_suppliers` 以外的字段，至少包括上表中的 `url`、`selected_blueword`、`blueword_execute_strategy_type`、`blueword_content_type`、`blueword_is_grab`、`blueword_maintain_duration`。

## 3. 媒介同步更新逻辑

同一条数据按同步次数处理。

### 3.1 第一次同步

媒介第一次同步过来的同一条数据，全量接收。

接收范围：

- 基础信息
- 供应商信息（`blueword_suppliers`）

### 3.2 第二次同步

1. 除 `blueword_suppliers` 以外的字段，可以直接更新。
2. `blueword_suppliers` 按下表处理。适用前提：第一次该数据为空，第二次同步有值。处理前先看本条记录当前是否已有值。

| 本条记录当前是否有值 | 处理 |
| --- | --- |
| 为空 | 全量接收 |
| 不为空 | 原文未给出后续动作，见第 6 节待确认项 |

## 4. 提醒逻辑

提醒项编号沿用原始编号：1、2、3、4、7 用于工单发布前；5、6 用于视频发布后。

| 编号 | 提醒项 |
| --- | --- |
| 1 | 合作金额 ≥ 4000，但操作类型为「做搜索」 |
| 2 | 需要抢词，且合集视频应使用 3 家供应商，但实际推送少于 3 家 |
| 3 | 使用了上词成功率低于 65% 的供应商 |
| 4 | 执行费用 ＞ KOC 预算 |
| 5 | `url` 变更 |
| 6 | 选定蓝词（`selected_blueword`）变更 |
| 7 | 上游需求变更。示例：上游需求变更_蓝词变更；上游需求变更_是否抢蓝词 |

合作金额计算：

```text
合作金额 = koc_budget × 10
```

### 4.1 工单发布前

#### 第一次判断

执行提醒项 1、2、3、4、7。

| 编号 | 是否判断 |
| --- | --- |
| 1 | 判断 |
| 2 | 判断 |
| 3 | 判断 |
| 4 | 判断 |
| 7 | 判断 |

#### 第二次判断

执行提醒项 1、7。提醒项 2、3、4 跳过。

| 编号 | 是否判断 | 补充条件 |
| --- | --- | --- |
| 1 | 判断 | `is_need_confirm = 3`（已确认）时，不再判断 |
| 2 | 跳过 | — |
| 3 | 跳过 | — |
| 4 | 跳过 | — |
| 7 | 判断 | — |

### 4.2 工单发布后

视频发布后，以下变更需要提醒，并用醒目红色标识：

| 编号 | 提醒项 | 展示 |
| --- | --- | --- |
| 5 | `url` 变更 | 醒目红色 |
| 6 | 选定蓝词（`selected_blueword`）变更 | 醒目红色 |

## 5. 判断公式

提醒项 1 的业务口径：

```text
合作金额 ≥ 4000，且操作类型 / 整单策略为「做搜索」
```

其中：

```text
合作金额 = koc_budget × 10
```

原文给出的判断公式：

```text
jsonData.koc_budget >= 4000 且 整单策略是做搜索
```

两条口径同时保留。若合作金额按 `koc_budget × 10` 计算，则「合作金额 ≥ 4000」对应 `koc_budget >= 400`，与 `jsonData.koc_budget >= 4000` 不一致。实现前需确认采用哪一条，见第 6 节。

## 6. 待确认项

1. 第二次同步时，第一次为空、第二次有值，且本条记录当前已有值：`blueword_suppliers` 不覆盖、部分更新，还是有其他处理，原文停在「如果不为空」。
2. 提醒项 1 的阈值：按「合作金额 = `koc_budget × 10`，合作金额 ≥ 4000」判断，还是按「`jsonData.koc_budget >= 4000`」判断。
